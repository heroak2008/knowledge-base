# 我的工作演进方向：决策收件箱与自动化分级（v1.18 候选设计）

> 方向来源：2026-11-17 产品方向讨论——"我的工作"将是未来最重要的工作台：Agent 为主做执行和串接，人做决策、判断、补充信息；配以决策参考与 AI 推荐辅助，后续逐步向智能化、自动化演进。
> 本文把该方向固化为设计决策：语义翻转、决策包结构、护栏、演进分级。

## 1. 语义翻转：从任务清单到决策收件箱

现状"我的工作"回答"**我该做哪件事**"（任务列表、facet 筛选、今日焦点）；目标态回答"**哪些 Agent 进程在等我表态**"。CoreALM-Next 的分工是 Agent 执行串接（M4）、人决策判断，因此人的默认界面从"队列"翻转为**决策收件箱**：Agent 推进到关键节点，携带证据请求人的批准/否决/补充信息，然后继续。

与既有设计的同构关系：

- 治理中心裁决队列 = **平台级**决策收件箱（面向裁决人角色，三道门）；
- 我的工作决策收件箱 = **任务级**决策收件箱（面向执行人角色，流程内人工中断点）；
- 同一 human-in-the-loop 模式在两个粒度出现，复用"留痕、理由必填、推荐人≠决策人"的治理规则；
- 续作现场（resume）保证决策节奏由人掌控，Agent 被打断不丢上下文；
- 经验中心/持续改进为 AI 推荐提供可解释语料（引用历史执行记录与经验卡片，不做黑箱打分）。

## 2. 决策包（Decision Package）结构

每条待决策项必须是完整决策包，不是通知：

```
[Agent 申请] <事项摘要> · 等你确认
├─ 事项：Agent 已完成什么、申请什么
├─ 证据：执行回执、验证结果、与标准逐条对照（链接 Trace/作业台现场）
├─ AI 推荐：建议 + 置信度 + 依据（同类历史通过率、规则集版本与误报率）
├─ 反方证据：未消除的风险与警告（必须呈现，禁止只给支持性证据）
└─ 操作：[批准] [否决·理由必填] [补充信息] [我要亲自看·跳作业台现场]
```

三条护栏（比功能本身更重要）：

1. **推荐必须可解释、可追责**：AI 推荐引用经验卡片与执行记录，用户能看到"为什么"；不能只有结论没有依据（对账口径同理）。
2. **反方证据必须呈现**：只给支持批准的证据等于诱导；未消除风险显式列出，如同"例外备案 ≠ 通过"。
3. **否决与人工复核必须留痕**：AI 推荐人 ≠ 决策人，AI 永远不是裁决者（M9 审核分离在个人工作台的同构延伸）。

## 3. 自动化分级：自动化程度本身是被治理的对象

不一次性设计"全自动"；自动化程度做成**分级、可回退、被治理**的配置：

| 阶段 | 模式 | 人的角色 | 治理机制 |
|---|---|---|---|
| L1（现状） | 人驱动，Agent 辅助 | 挑任务、下指令 | — |
| **L2 决策收件箱** | Agent 推进到节点，人批准 | 高频轻决策 | 决策包 + 推荐 + 留痕 |
| L3 白名单自动 | 低风险类别自动通过，异常升级 | 处理例外 | 自动通过事项进**上线观察**（复用 M13），指标回退即降级 |
| L4 目标态 | 大部分流程自动，人处理真正例外 | 定方向、定标准 | 自动化范围是 M6 管辖的**版本化标准**，调整走治理中心裁决 |

推进原则：L3→L4 由持续改进闭环（评测数据集验证 uplift）驱动，每步有验证依据、可回退——演进路径本身符合平台治理哲学。

## 4. 原型落点（v1.17 增补 rev4）

"我的工作"页顶部新增**决策收件箱区**：3 个决策包样例（转测交付申请 / 知识固化申请 / 改进回退升级），含 AI 推荐与置信度、反方证据、四类操作（演示弹窗）。该区在 L2 形态下置于任务队列之前——先处理表态，再看队列。
